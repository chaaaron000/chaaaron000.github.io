AI 작업 환경

여러 AI를 역할별로 나눠 쓰는 방식. 개발 중인 세 프로젝트에 공통으로 적용하고 있습니다.

터미널 작업 공간 Herdr에 Claude Code, Codex 같은 AI 도구를 여러 개 띄우고, 직접 만든 플러그인 herdr-loadout의 프로필로 역할별 모델과 추론 강도를 정합니다.

  1. 판단 기준AGENTS.md에 판단 우선순위(내 요청, 정리 문서, 원천 자료, 코드, AI 추론 순)와 프로젝트 규칙을 적습니다.
  2. 근거와 정리결정 기록과 자료, 정리본을 나눠 두고 AI가 근거를 찾아 쓰게 합니다. 「화면 건너편의 너」는 raw와 wiki 폴더로 나누고, PerfectHer와 Caldera는 정리본 위치가 조금 다릅니다.
  3. 브리프와 워커오케스트레이터는 작업을 쪼개 브리프만 쓰고, 구현과 검수는 새 워커가 맡습니다.
  4. 확인완료 보고를 그대로 믿지 않고 문법 검사기, 테스트, 실제 플레이 결과로 확인합니다.
  5. 기록피드백과 시행착오를 메모 파일에 쌓아 같은 실수를 반복하지 않게 합니다.

브리프에는 목표, 범위, 이미 정한 사항, 완료 기준, 보고 파일 경로를 적습니다.

01 / 06개발 중

Caldera

협동 생존 게임. 인디 게임으로 어디까지 해 볼 수 있는지 확인하는 프로젝트입니다. 평면도를 걸어 다닐 수 있는 레벨로 만드는 도구를 직접 만들어 씁니다.

인원
1명 (AI 에이전트와 함께)
기술
Unity, FishNet, Steam Audio, Node, Three.js, Blender

레벨 설계 편집기 브라우저에서 벽, 문, 방을 편집

  • 한 층의 평면도를 구조화된 JSON 데이터로 저장합니다.
  • 방과 면적은 편집할 때마다 다시 계산하고, 검사 결과는 화면에 핀으로 표시합니다.
  • 키 하나로 2D, 3D 탑뷰, 1인칭 보기를 전환합니다.
  • 빌드 단계와 npm 의존성 없이 Node 22만으로 실행됩니다.

사람과 에이전트가 같은 도면을 편집합니다. 서버가 열어 둔 도면을 실시간 세션으로 유지하고, 브라우저 탭과 MCP로 연결된 에이전트가 같은 세션에서 편집합니다. 수정할 곳은 도면 위에 메모 핀을 남겨 알려 줍니다.

도면 데이터 구조와 편집 규칙은 제가 정했고, 평면도 배치는 에이전트가 MCP로 합니다.

평면도에서 레벨까지 에이전트가 도면을 직접 읽고 측정

  1. 평면도 이미지, PDF
  2. 에이전트도면 읽기와 측정
  3. 나편집기에서 수정 지시
  4. 에이전트게임용 FBX 내보내기
  5. 걸어 다닐 수 있는 레벨

에이전트가 floorplan-to-game-level 스킬로 평면도를 읽고 치수를 잽니다. 저는 편집기에서 메모 핀으로 수정할 곳을 지시하고, 에이전트가 반영합니다. 마지막으로 에이전트가 게임용 FBX로 내보내고 검수 스크립트를 실행합니다.

기술 검증 본 개발 전, 위험 요소를 실제 레벨에서 확인

100%왕복 250ms, 손실 5% 조건에서 지연 보상 판정 일치명중과 부위 판정 기준입니다. 지연 보상은 직접 구현했습니다.
172방 181통로음향 그래프총성 전파를 그래프로 계산하고, 문 차폐는 Steam Audio로 처리합니다.
159문 5층검증에 쓴 레벨FishNet 전용 서버, 근접 음성과 무전기, Linux 서버 저장과 재시작을 확인했습니다.
저장소는 비공개입니다.

02 / 06개발 중

PerfectHer

심리적 공포 비주얼 노벨. 프로토타입과 아트 시안은 AI와 함께 Blender, ComfyUI로 만들고, 최종 캐릭터는 아트 팀원이 그립니다.

인원
2명 (개발 1, 아트 1)
기술
Unity, Naninovel, Python, Blender MCP, ComfyUI

사건 데이터 편집 시스템 사건 하나당 JSON 파일 하나

  1. 나노드 편집기
    에이전트CLI
  2. 같은 저장 경로
  3. 사건 JSON
  4. 웹 시안, Unity 사본
  • 사람용 편집기와 에이전트용 CLI가 같은 저장 경로를 씁니다. 사건 파일마다 쓰기 잠금을 걸고, 읽을 때의 해시와 현재 파일의 해시를 비교합니다. 읽은 뒤에 파일이 바뀌었으면 저장하지 않습니다.
  • 시안에서 확인한 사건이 그대로 게임에 들어갑니다. 저장할 때마다 웹 시안용 사본과 Unity용 사본을 함께 만듭니다.
  • git diff에는 수정한 줄만 나옵니다. 사건 JSON의 키 순서와 줄 바꿈 규칙을 고정했습니다.

QA 플레이 코드 리뷰를 대체한 검증

다른 모델에게 코드 리뷰를 맡겨 봤지만 실제 버그는 거의 잡지 못했습니다. 그래서 QA 전담 에이전트가 Unity Play 모드에서 직접 플레이하도록 바꿨습니다.

  1. 구현 에이전트기능을 구현합니다.
  2. QA 에이전트정답 경로와 오답 경로를 끝까지 직접 플레이합니다. 대사 도중 저장, 연타, 되감기도 시험합니다.
  3. QA 에이전트버그를 심각도별로 정리해 보고하고, 구현 에이전트가 수정합니다.
  4. QA 에이전트찾은 버그의 재현 절차를 회귀 스크립트로 남깁니다.
  5. 나QA 왕복은 최대 3번으로 제한합니다. 그 뒤에도 남은 문제는 제가 판단합니다.

27개 경로회귀 테스트. 대사 순서, 최종 상태, 저장 후 불러오기 결과, 콘솔 오류를 매번 비교합니다.

AI 시안 파이프라인 프로토타입용 3D 배경과 캐릭터 시안

최종 캐릭터는 아트 팀원이 그립니다. 여기서 만드는 이미지는 프로토타입에 쓰고 방향을 맞추기 위한 시안입니다.

  1. 3D 배경에이전트가 Blender MCP로 모델링하고 카메라 구도를 잡습니다.
  2. 캐릭터 시안에이전트가 comfy CLI로 ComfyUI 이미지를 생성합니다.
  3. 합성과 1차 검수검수 에이전트가 확대해 확인합니다.
  4. 선택과 반려프로토타입에 쓸지 제가 판단합니다.

GPU 큐. GPU 하나를 ComfyUI 생성과 Blender 렌더가 나눠 쓰도록, 오케스트레이터가 사용 순서를 큐로 관리합니다.

미션 커스텀 인스펙터 GUID를 복사하고 대상을 다시 찾던 작업 제거

원하는 화면을 그림판으로 스케치해 Codex에 구현을 맡겼습니다. 마음에 들지 않는 부분은 고치게 하고, 좋았던 부분은 어디가 왜 좋은지 짚어 줬습니다. 좋다고 전한 것은 탭으로 나눠 편집하는 구성과, 드롭다운에는 Title을 보여 주고 저장은 GUID로 하는 구조입니다.

GreenClean

카드로 오염된 타일을 정화하는 전략 퍼즐. 이미 Blackboard에 기록되는 상태라면 조건 조합만으로 마스코트 반응을 추가할 수 있는 구조를 만들었습니다.

기간
2026.05, 2주
인원
5명
기술
Unity, C#, ScriptableObject

반응 테이블 에디터 조건 데이터로 정하는 마스코트 반응

스키마에 등록된 키만 고를 수 있고, 고른 키의 자료형에 맞춰 입력 칸이 바뀌는 커스텀 인스펙터입니다.

이미 Blackboard에 기록되는 상태라면 새 판단 코드 없이 조건 조합만으로 반응을 추가할 수 있습니다. 콤보 3, 5, 7, 10회 반응을 이렇게 추가했고, 같은 구조를 「화면 건너편의 너」에서 재사용했습니다.

Blackboard와 조건 트리 게임 로직과 반응 조건 분리

콤보 횟수, 약품 사용 횟수처럼 마스코트가 반응할 상태가 계속 늘어날 것으로 예상했습니다. 게임 로직은 값만 기록하고, 반응 시스템은 값 변경 알림을 받아 조건을 평가합니다.

// 게임 로직: 값만 기록
blackboard.TrySet(BlackboardKey.COMBO_COUNT, currentCombo);

// 반응 시스템: 변경 알림만 받아 평가
blackboard.ValueChanged += EvaluateReaction;
  • 키마다 INT, FLOAT, BOOL, STRING 중 하나를 스키마로 고정하고, 자료형이 다른 값은 거부합니다.
  • 시작값과 런타임 값을 분리해 스테이지마다 초기화합니다.
  • Unity 직렬화의 한계 때문에 object 대신 자료형별 값을 따로 보관합니다.

조건 트리. 명일방주 모작을 하다가 원작 버프 데이터가 조건을 트리로 조합하는 것을 보고 그 방식을 적용했습니다. 조건 노드는 값 비교 6가지와 And, Or, Not, AlwaysTrue, IsValueChanged입니다.

  • Blackboard와 조건 트리

MixterPiece

물감을 섞어 그림을 완성하는 논리 퍼즐. AI 활용 게임 개발 대회 출품작이고 브라우저에서 플레이할 수 있습니다.

기간
2026.07 – 08, 3주
인원
3명
기술

벽 시스템과 벽 에디터 물감 확산을 막는 벽과 인스펙터 편집 도구

벽 시스템. 벽은 물감이 퍼지는 것을 막습니다. 격자 상태 데이터에 벽 정보와 이동 가능 검사를 추가하고, 화면의 벽 표시와 연결했습니다.

벽 에디터. 스테이지 데이터 인스펙터에 격자를 그리고, 셀 경계를 클릭해 벽을 넣고 뺍니다. 되돌리기와 전체 제거를 지원합니다. 코드를 고치지 않고 스테이지 벽 배치를 편집합니다.

팀 AI 개발 워크플로 LLM Wiki, AGENTS.md, unity-cli

AI가 기획과 구조를 모른 채 코드를 고치거나 Unity에서 동작하지 않는 결과를 내는 문제가 있었고, 팀원마다 AI를 쓰는 방식도 달랐습니다.

기획과 개발 자료를 LLM Wiki로 정리해 필요한 문서만 AI에 주고, AGENTS.md에 작업 규칙과 unity-cli 컴파일 확인 절차를 고정해 팀과 공유했습니다.

기여 범위 3명 팀에서 맡은 구현

  • 벽 데이터, 이동 가능 검사, 벽 표시 연결 (격자 상태의 최초 구현은 팀원)
  • 벽 에디터
  • 색각 보정, 색상 심볼 표시 옵션을 설정 화면에 연결 (색각 보정 재질은 팀원 구현)
  • 마스터, 배경음악, 효과음 볼륨을 오디오 믹서에 연결
  • 팀 AI 개발 워크플로 구성

Photon Fusion 전환 네트워크 구조 교체 제안

기존 RPC 방식은 오류 원인을 추적하기 어려웠고, 상태와 애니메이션 동기화가 자주 어긋났습니다. 이미 만든 기능을 다시 만드는 비용과, 같은 방식으로 계속 확장할 때 반복될 비용을 비교해 근거를 정리했고, 팀의 동의를 얻어 전환했습니다.

몬스터 FSM 리팩터링 기존 동작을 유지한 상태 머신 전환

팀원이 만든 몬스터 행동 알고리즘을 분석해 대기, 경계, 추적, 공격 네 상태로 나누고, 기존 동작을 유지한 채 Fusion 상태 머신으로 옮겼습니다. 새로 작성하기 전에 기존 코드가 왜 그렇게 동작하는지부터 파악했습니다.

출시 전 난이도 조정 지인 플레이테스트와 합의

1년 내내 플레이한 팀의 난이도 감각이 무뎌졌다고 판단해 지인들에게 플레이테스트를 부탁했습니다. 피드백을 얼마나 반영할지 의견이 갈렸고, 도입부는 그대로 두고 마지막 스테이지 난이도만 올리기로 합의했습니다.

출시 후에도 Steam 평가에는 쉽다는 의견이 많았습니다. 소수의 지인 테스트만으로는 한계가 있다는 것을 배웠습니다.

기여 범위 3명 팀에서 맡은 구현

  • Photon Fusion 전환 제안과 네트워크 구조 전환
  • 몬스터 상태 머신 리팩터링 (원래 행동 알고리즘은 팀원 구현)
  • Vivox 음성 채팅 연동: Photon 세션 이름으로 위치 기반 채널에 참가, 플레이어 위치를 음성 처리에 반영, 설정 화면에서 마이크와 출력 장치 변경

커밋 단위 기여는 코드 아카이브에서 확인할 수 있습니다.
