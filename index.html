AI 작업 환경

여러 AI를 역할별로 나눠 쓰는 방식. 개발 중인 세 프로젝트가 모두 이 위에서 돌아갑니다.

터미널 작업 공간 Herdr에 Claude Code, Codex 같은 AI 도구를 여러 개 띄우고, 직접 만든 플러그인 herdr-loadout 프로필로 역할별 모델과 추론 강도를 정합니다.

  1. 판단 기준AGENTS.md에 우선순위(내 요청, 정리 문서, 원천 자료, 코드, AI 추론 순)와 프로젝트 규칙
  2. 근거와 정리결정 기록과 자료는 raw, 정리본은 wiki. AI가 근거를 찾아 씁니다
  3. 브리프와 워커오케스트레이터는 일을 쪼개 브리프만 쓰고, 구현과 검수는 새 워커가 맡습니다
  4. 확인완료 보고를 믿지 않고 문법 검사기, 테스트, 실제 플레이 결과로 판단
  5. 기록피드백과 겪은 함정을 메모 파일에 쌓아 같은 실수를 막습니다

브리프에는 목표, 범위, 정한 결정, 완료 기준, 보고 파일 경로를 담습니다.

직접 만든 도구 이 방식을 받치는 세 가지

herdr-loadout

역할마다 쓸 도구, 모델, 추론 강도를 프로필로 등록하는 Herdr 플러그인. 오케스트레이터가 적은 컨텍스트로 조회해 워커를 띄웁니다.

저장소 보기

floorplan-to-game-level

에이전트가 건축 평면도를 직접 읽고 재서 IFC와 게임용 FBX로 만들고, 비매니폴드, z-fighting, 캡슐 도달 가능성까지 검사하는 스킬 모음.

Naninovel 공식 언어 서버를 꺼내 저장소에서 직접 구동합니다. 에이전트가 시나리오를 고치면 문법 진단을 통과해야 다음 단계로 넘어갑니다.

02 / 07개발 중

Caldera

협동 생존 게임. 평면도에서 걸어 들어갈 수 있는 레벨까지, 인디 규모로 어디까지 손을 뻗을 수 있는지 확인합니다.

인원
1명 (AI 에이전트와 함께)
기술
Unity, FishNet, Steam Audio, Node, Three.js, Blender

레벨 설계 편집기 브라우저에서 벽, 문, 방을 편집

  • 한 층 평면도를 구조 데이터(JSON)로 둡니다.
  • 방과 면적은 편집할 때마다 다시 계산하고, 검사 결과를 화면에 핀으로 띄웁니다.
  • 키 하나로 2D, 3D 탑뷰, 1인칭 사이를 오갑니다.
  • 빌드 단계와 npm 의존성 없이 Node 22 하나로 돌아갑니다.

사람과 에이전트가 같은 도면을 고칩니다. 서버가 연 도면을 실시간 세션으로 쥐고, 브라우저 탭과 MCP로 붙은 에이전트가 같은 세션을 편집합니다. 고칠 곳은 도면 위 메모 핀으로 알려 줍니다.

평면도에서 레벨까지 에이전트가 도면을 직접 읽고 잽니다

  1. 평면도 이미지, PDF
  2. 에이전트도면 추적
  3. 나편집기에서 수정
  4. 에이전트게임용 FBX 내보내기
  5. 걸어 다닐 수 있는 레벨

에이전트가 floorplan-to-game-level 스킬로 도면을 추적합니다. 저는 편집기에서 메모 핀으로 고칠 곳을 지시하고 에이전트가 반영합니다. 에이전트가 게임용 FBX로 내보낸 뒤 검수 스크립트를 실행합니다.

기술 검증 본 개발 전에 위험한 요소를 실제 레벨에서 확인

100%지연 보상 판정 일치직접 구현. 왕복 250ms, 손실 5%에서 명중과 부위 판정
172방 181통로음향 그래프총성 전파를 그래프로 계산, Steam Audio로 문 차폐
159문 5층검증에 쓴 레벨FishNet 전용 서버, 근접 음성과 무전기, Linux 서버 저장과 재시작

역할 구분

제가 정한 것

  • 도면 데이터 구조와 편집 규칙
  • 사람과 에이전트가 한 세션을 공유하는 구조
  • 검사 항목과 레벨 수치 기준

AI에게 맡긴 것

  • 편집기 구현과 3D, 1인칭 뷰어
  • 평면도 추적과 배치 초안
  • FBX 내보내기 검수 스크립트 실행
저장소는 비공개입니다.

PerfectHer

심리적 공포 비주얼 노벨. 프로토타입과 아트 시안은 AI와 함께 Blender, ComfyUI로 뽑고, 캐릭터는 아트 팀원이 그립니다.

인원
2명 (개발 1, 아트 1)
기술
Unity, Naninovel, Python, Blender MCP, ComfyUI

사건 데이터 편집 시스템 사건 하나가 JSON 하나

  1. 나노드 편집기
    에이전트CLI
  2. 같은 저장 경로
  3. 사건 JSON
  4. 웹 시안, Unity 사본
  • 사람용 편집기와 에이전트용 CLI가 같은 저장 경로를 씁니다. 사건마다 쓰기 잠금을 잡고, 읽은 판(해시)과 지금 파일을 견줍니다. 읽은 뒤 파일이 바뀌었으면 쓰지 않습니다.
  • 시안에서 확인한 사건이 그대로 게임에 들어갑니다. 저장할 때마다 웹 시안용 사본과 Unity용 사본을 한 번에 씁니다.
  • git에서 고친 줄만 보입니다. 사건 JSON의 키 순서와 줄 바꿈 규칙을 고정했습니다.

QA 플레이 코드 리뷰를 대체한 검증

다른 모델에게 코드 리뷰를 맡겨 봤지만 실제 버그는 거의 잡지 못했습니다. QA 전담 에이전트가 Unity Play 모드에서 직접 플레이하도록 바꿨습니다.

  1. 구현 에이전트기능을 구현합니다.
  2. QA 에이전트정답 길과 오답 길을 끝까지 직접 플레이합니다. 대사 중간 저장, 연타, 되감기도 해 봅니다.
  3. QA 에이전트버그를 심각도별로 정리해 보고하고, 구현 에이전트가 수정합니다.
  4. QA 에이전트잡은 버그의 재현 절차를 회귀 스크립트로 남깁니다.
  5. 나QA 왕복 상한은 3번입니다. 그 뒤에도 남은 문제는 제가 판단합니다.

27개 경로회귀 테스트. 대사 순서, 끝 상태, 저장 후 불러오기, 콘솔 오류를 매번 비교합니다.

AI 시안 파이프라인 프로토타입용 3D 배경과 캐릭터 시안

최종 캐릭터는 아트 팀원이 그립니다. 여기서 뽑는 이미지는 프로토타입과 방향을 맞추기 위한 시안입니다.

  1. 3D 배경에이전트가 Blender MCP로 모델링하고 카메라 구도를 잡습니다.
  2. 캐릭터 시안에이전트가 ComfyUI로 생성합니다.
  3. 합성과 1차 검수검수 에이전트가 확대해 확인합니다.
  4. 선택과 반려프로토타입에 쓸지 제가 판단합니다.

GPU 큐. GPU 하나를 ComfyUI 생성과 Blender 렌더가 줄 서서 나눠 씁니다.

역할 구분

제가 정한 것

  • 사건 데이터 꼴과 저장 규칙
  • QA 흐름과 버그 심각도 기준
  • 프로토타입용 시안 선택과 반려

AI에게 맡긴 것

  • 편집기, CLI, Unity 기능 구현
  • QA 플레이와 회귀 스크립트 작성
  • 3D 배경, 캐릭터 시안 생성과 1차 검수

반응 테이블 에디터 조건을 데이터로 넣으면 마스코트가 반응

스키마에 등록된 키만 고를 수 있고, 고른 키의 자료형에 맞춰 입력 칸이 바뀌는 커스텀 인스펙터입니다.

콤보 3, 5, 7, 10회 반응을 새 판단 코드 없이 조건 조합만으로 추가했고, 같은 구조를 「화면 건너편의 너」에서 다시 썼습니다.

Blackboard 시스템 게임 로직과 반응 시스템 분리

콤보 횟수, 약품 사용 횟수처럼 마스코트가 반응할 상태가 계속 늘어날 것이 보였습니다. 로직은 값만 기록하고, 반응 쪽은 값이 바뀌었다는 알림만 받아 평가합니다.

// 게임 로직: 값만 기록
blackboard.TrySet(BlackboardKey.COMBO_COUNT, currentCombo);

// 반응 시스템: 변경 알림만 받아 평가
blackboard.ValueChanged += EvaluateReaction;
  • 키마다 INT, FLOAT, BOOL, STRING 중 하나를 스키마로 고정하고, 다른 자료형 값은 거부
  • 시작값과 런타임 값을 분리해 스테이지마다 초기화
  • Unity 직렬화 한계 때문에 object 대신 자료형별 값을 명시적으로 보관

조건 트리 반응 조건을 노드 조합으로

명일방주 모작을 하며 원작 버프 데이터가 조건을 트리로 조합하는 것을 보고, 그 방식을 가져왔습니다.

  • 값 비교 6가지
  • And
  • Or
  • Not
  • AlwaysTrue
  • IsValueChanged

MixterPiece

물감을 섞어 그림을 완성하는 논리 퍼즐. AI 활용 게임 개발 대회 출품작이고 브라우저에서 플레이할 수 있습니다.

기간
2026.07 – 08, 3주
인원
3명
기술
Unity, C#, WebGL

벽 에디터 인스펙터에서 셀 경계를 클릭해 벽을 편집

  • 스테이지 데이터 인스펙터에 격자를 그리고, 셀 경계를 클릭해 벽을 넣고 뺍니다.
  • 되돌리기와 전체 제거를 지원합니다.
